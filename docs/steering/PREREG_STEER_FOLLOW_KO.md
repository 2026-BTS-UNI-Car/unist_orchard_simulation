# 단일 열 추종 사전등록 (steer_follow_v1)

- 작성: 2026-11-12. 등록 번호 `steer_follow_v1`. 기계가 읽는 사본: `PREREG_STEER_FOLLOW.json`(`follow_matrix.py --prereg`의 출력과 같아야 한다. 시험 `sim/ubts/test_steering_follow_matrix.py`가 본다).
- 대상: 열 추종 제어기 `sim/ubts/closed_loop/steer_control.py`(실행기 제어기 자리의 `{"kind": "row_follow"}`, 기본값 그대로).
- 이 문서는 제어기를 폐루프로 돌리기 전에 썼다. 이 커밋까지 한 것은 합성 스냅샷 단위 시험과 정지 스캔 자리 시험뿐이다(차가 움직이는 실행 0회).
- 모든 수치는 자리값이다. 결과는 **자리값 기반 SIM 결과**이고 실차 성능이 아니다.
- 설계 근거: `DESIGN_v2_KO.md`(8항 속도·열 끝, V2-4, V2-7), `DESIGN_v1_KO.md` 1.1절(열 끝 정지 위치)·7.1절(NOMINAL 클래스 한도), `SIM_ACCEPTANCE_KO.md` A22.

## 1. 무엇으로 재나

| 항목 | 값 |
|---|---|
| 시뮬레이터 | F-SIM T1 리그, 실행기 포함(`tools/row_executor/sim_in_loop_steer.py`): 실제 실행기 루프와 Runner(front_steer, MOTOR, 단일열) ↔ 브리지 클라이언트 ↔ 호스트 브리지 ↔ MCU 펌웨어·구동기 모델 ↔ 조향 플랜트 ↔ 세계 ↔ S2 스캔·IMU |
| 세계 | W0 평지에 기둥 두 줄. y = ±1.75 m, x = −4.5 … 24.0 m, 간격 1.5 m, 반지름 0.12 m, 40개. 통로 중심선 y = 0, 열 끝(마지막 기둥 선) x = 24.0 m |
| 출발 | (0, 0, 0°)에서 정지. 조건에 따라 바꾼다 |
| 조작 | 리그의 조작자 흉내(Start, Arm, 한 번 누름). 다시 누르지 않는다(`auto_repress` 끔) |
| 길이 | 150 s. 종결 뒤 3.2 s 더 본다 |
| 실행기 설정 | 리그가 만드는 기본 설정(`steer_executor_config`). 바꾸지 않는다 |

W1(과수원 한 열)은 G-SIM(Gazebo) 세계다. F-SIM에는 없다. 그래서 W0의 기둥 두 줄을 쓴다(기존 `W0_ROWS`와 간격·폭·반지름이 같고 x = 24.0 m에서 끝나게만 했다). W2(10/10 통로)와 G-SIM은 이 등록에 없다.

## 2. 조건 (11종, 15회)

| 조건 | seed | 바꾸는 것 | 기대 |
|---|---|---|---|
| `nominal` | 0, 1, 2, 3, 4 | 없음 | 열 끝 정지 |
| `lateral_p040`, `lateral_n040` | 0 | 출발 횡 위치 +0.40 m, −0.40 m | 열 끝 정지 |
| `heading_p8`, `heading_n8` | 0 | 출발 방향 +8°, −8° | 열 끝 정지 |
| `steer_zero_p2`, `steer_zero_n2` | 0 | 조향 영점 오차 +2.0°, −2.0°(프로파일 `steer_zero_offset_deg`) | 열 끝 정지 |
| `side_pull` | 0 | 한쪽 쏠림: `curvature_wander` 평균 +0.6 °/m(기본 −0.15, 프로파일 허용 범위의 끝) | 열 끝 정지 |
| `lidar_dropout_0p2` | 0 | 20 s에 LiDAR 0.2 s 끊김(신선도 한도 0.45 s 안) | 멈추지 않고 열 끝 정지 |
| `lidar_stale_1p0` | 0 | 20 s에 LiDAR 1.0 s 끊김(한도 밖) | `stale_lidar`로 일시정지, 다시 출발하지 않음 |
| `obstacle` | 0 | 중심선 x = 12.0 m에 기둥 하나 | `obstacle_ahead`로 종결, 접촉 없음 |

seed마다 리그의 난수 흐름이 다르다(run별 영점 오차, 쏠림, 센서 잡음). 쏠림 평균을 1.3 °/m로 두는 값은 프로파일 범위 검사가 거부해 쓰지 않았다(설정 확인만 했고 실행은 아니다).

## 3. 재는 값

참값은 평가에만 쓴다(리그 trace의 `truth_*` 칸, 참값 격리 역할 evaluator).

- 구간: 구동 명령이 처음 0보다 큰 틱부터 마지막으로 0보다 큰 틱까지('주행 구간').
- 횡오차: 차체 중심(footprint 중심)의 y. 방향 오차: 차 방향각(열 축이 x다).
- 열 끝 정지 위치 e = 정지 때 앞범퍼 x − 24.0 m. 앞범퍼 = 중심 + 0.61 m·cos(방향).
- 최소 여유: 차체 사각형(1.22 × 0.70 m)에서 기둥 표면까지의 거리의 최솟값(전 구간).
- 일시정지: 주행 시작 뒤의 PAUSED 상태 전이와 그 이유.
- 종결 뒤 조향: A22 규칙 그대로(`measure.command_after`, 종결 시각부터 3 s. 일시정지로 끝난 경우 첫 일시정지 시각부터).
- 출발을 어긋나게 둔 네 조건(`lateral_*`, `heading_*`)은 횡 RMSE·p95와 방향 RMSE를 주행 6.0 m 뒤부터 잰다(주시거리 2.0 m의 3배). 0.40 m 출발은 그 자체가 p95 한도보다 크기 때문이다. 최댓값 한도는 처음부터 잰다.

## 5. 규칙

1. 결과를 본 뒤에는 기준·조건·재는 방법을 바꾸지 않는다. 바꿔야 하면 다시 돌리기 전에 6절에 수정 사항을 이유와 함께 먼저 적고 커밋한다.
2. 제어기는 고칠 수 있다. 고칠 때마다 결과 문서의 반복 기록에 무엇을 왜 바꿨는지, 커밋, 그때의 표를 남긴다. 앞 반복의 실패를 지우지 않는다.
3. 조건 일부만 돌린 결과(`--only`)는 전체 판정이 아니다(`complete: false`).
4. 동시에 도는 프로세스는 4개 이하다. 시간 수치는 호스트 부하에 따라 달라지는 참고값이다.

## 7. 이 등록이 보이지 않는 것

- 실차 성능. 모든 값이 자리값이다(조향 장치 치수, 속도표, 지연, 한도).
- G-SIM의 W1, 10/10 통로(W2), 굽은 열, 경사, 빠진 나무, 열 끝 너머의 벽.
- 구동기 사전값 층(L1), 국소 격자 층(L2), GNSS 층(L3). 제어기에 자리만 있고 꺼져 있다.
- IMU 끊김, 조작 신호 끊김, MCU·브리지 고장(P4 수용 검사가 따로 본다).

## 8. 실행

`sim/ubts`에서:

```
python -B -m steering.safety_scripts.follow_matrix --out <저장소 밖 폴더> --workers 4
python -B -m steering.safety_scripts.follow_matrix --prereg      # 이 등록의 JSON
```

run마다 `<폴더>/follow_<조건>_s<seed>/`에 `TRACE.npz`, `SERIAL.jsonl`, `EXECUTOR.jsonl`, `RESULT.json`이 생기고, 표는 `<폴더>/FOLLOW_MATRIX.json`이다. 결과와 그림은 `STEER_FOLLOW_RESULT_KO.md`에 적는다.
