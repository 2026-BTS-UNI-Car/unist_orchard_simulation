## 2. 자산 규칙

### 2.1 폴더와 이름

- 경로: `docs/assets/<묶음>/<이름>.<확장자>`. 묶음은 `rover`(차량 모델), `world`(월드), `sensors`(센서 화면), `dashboard`(화면),
  `video`(GIF·영상), `diagrams`(그림으로 만든 도식), `photos`(실물 사진) 가운데 하나다.
- 이름: 소문자 영어·숫자·`_`만. 확장자는 `png`, `jpg`, `gif`, `webp`, `svg`, `mp4`, `webm`.
- 결과 문서에 딸린 그래프는 그 문서 옆 폴더(`docs/steering/figures/` 등)에 둔다. README는 그 그림을 그대로 가리킨다(복사하지 않는다).

### 2.2 크기 상한 (바이트)

| 대상 | 상한 |
|---|---|
| 그림(PNG, JPEG, WebP, SVG) 한 개 | 1,000,000 미만 |
| GIF·영상 한 개 | 10,000,000 미만 |
| README 첫 화면 GIF(`role: readme_hero`) | 5,000,000 이하, 폭 640 px 이하 |
| `docs/` 아래 모든 그림·영상의 합계 | 50,000,000 이하 |

- 상한은 `docs/assets/`뿐 아니라 `docs/` 아래 모든 그림·영상에 같이 건다(공통 규칙 8).
- 사진처럼 보이는 렌더는 JPEG(품질 85~88), 글자·선이 많은 그림은 PNG. 폭은 1280 px 이하로 줄인다.

### 2.3 매니페스트 `docs/assets/ASSETS.json`

`docs/assets/`의 모든 파일이 한 줄씩 있다(없는 파일, 남는 파일 모두 검사가 잡는다). 칸:

| 칸 | 뜻 |
|---|---|
| `path`, `kind`, `bytes`, `sha256`, `width`, `height` | 파일과 그 크기. 종류는 `image` / `animation` / `video` |
| `tag` | 출처 표시. 다섯 가지 가운데 하나: `[SIM · 자리값]`, `[현장 기록 · YYYY-MM-DD]`, `[도식]`, `[사진]`, `[계획 · 미구현]` |
| `caption` | 그림 설명(문서 캡션의 바탕) |
| `origin` | `source`(원본 파일. 저장소 밖이면 `<runs>/...`로 적는다), `made_by`(원본을 만든 도구·이미지·프로필·날짜), `command`(다시 만드는 명령), `tools`(도구 판), 원본 SHA-256 |
| `privacy` | `metadata`(지운 메타데이터), `visual_check`(눈으로 본 날짜, 본 파일의 SHA-256, 본 것) |
| `role` | 선택. `readme_hero`면 2.2절 첫 화면 상한 |

### 2.4 게시 전 점검

1. 파일을 직접 열어 본다(GIF는 처음·가운데·끝 프레임). 사람, 계정 이름, 주소, 도메인, 토큰, GNSS 좌표, 위치가 찍힌 지도가 없는지 본다.
   본 뒤 `make_assets.py --mark-checked <이름> --note "<본 것>"`. 기록은 그 파일의 SHA-256에 묶인다. 파일이 바뀌면 다시 봐야 한다.
2. 메타데이터를 남기지 않는다: PNG 문자·EXIF 덩어리, JPEG EXIF·XMP·IPTC·주석, GIF 주석·모르는 응용 블록, MP4 위치 정보.
   `make_assets.py`는 원본을 다시 인코딩해 이것들을 남기지 않는다.
3. 문서에서 `docs/assets/`의 그림을 쓸 때는 그림 줄이나 그 아래 3줄 안에 매니페스트의 출처 표시를 적는다.
4. 좌표 모양 숫자(A16 규칙, `sim/ubts/field_world/coord_lint.py`)와 개발 PC·NAS·장비의 절대 경로가 문서와 매니페스트에 없어야 한다.

### 2.5 검사

```bash
python -I tools/steer_sim/check_assets.py          # 매니페스트, 크기, 출처 표시, 메타데이터, 좌표, 경로, 문서 링크
python -B -m pytest -q -p no:cacheprovider sim/ubts/test_steering_check_assets.py   # 검사 도구의 시험 17개
python -B tools/steer_sim/make_assets.py --list    # 자산 목록과 원본
```

- 검사 도구의 시험은 위반 예를 하나씩 넣어 잡는지 본다: 상한 넘는 그림, 매니페스트에 없는 파일·없어진 파일, 출처 표시 없는 그림, 모르는
  출처 표시, 좌표 모양 숫자(매니페스트·문서), 절대 경로, 눈으로 본 기록과 다른 파일, 해시·크기 어긋남, PNG 문자·GIF 주석·JPEG EXIF,
  첫 화면 GIF 상한, 이름 규칙, 깨진 링크·앵커, `docs/` 그림·영상 합계.
- 문서 링크는 README와 `docs/` 아래 모든 `.md`에서 본다. 상대 링크의 파일과 `#제목` 앵커가 있어야 한다.
  주제 폴더(`docs/steering/` 등)의 옛 문서에서 경로처럼 보이지 않는 대상(수식 `P[n](7.3절)`처럼 대괄호 뒤에 괄호가 온 글)은 경고로만 낸다.
- `make_assets.py`는 같은 원본과 같은 도구 판으로 같은 바이트를 만든다(2026-11-13 확인: 두 번 만들어 매니페스트가 같다).

## 3. 글쓰기

- 잰 것만 쓴다. SIM 수치에는 "자리값 기반 SIM 결과이며 현장 성능이 아니다"를 붙인다. 실패와 불합격도 지우지 않는다.
- 결과 칸은 네 값 가운데 하나다: 합격, 불합격, 보고(합격선 없이 값만), 미실행.
- 검증하지 않은 것을 끝난 것처럼 쓰지 않는다. 아직 없는 그림은 `[계획 · 미구현]`으로 자리만 둔다.
- 처음 보는 사람 점검표: README만 읽고 (1) 목표, (2) 차량, (3) 제어 구조, (4) 알고리즘, (5) 결과, (6) 한계에 답할 수 있어야 한다.

## 4. 커밋하지 않는 것

측정 결과 원본, 캡처 원본(프레임, 원본 PNG), 로그, 임시 스크립트, 개인 설정. 이것들은 저장소 밖 기록 폴더에 둔다(`.gitignore`의
`runs/`, `data/`, `artifacts/`, `tools/out/` 등). 커밋 전에 `git status --short`로 확인한다.
