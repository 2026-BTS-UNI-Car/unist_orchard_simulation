## 0. 등록 전에 돌린 것

등록한 seed(개발 100~104, 판정 3000~3004)로 돌린 run은 0회다. 등록 전에는 조건 주입기의 배선만 확인했다(seed 9000과 0, 등록 밖, 판정에 쓰지 않음):

- seed 9000으로 12조건 1회씩(`nominal`, `curve_l30`, `gap3_both`, `endpost_1p2`, `table_x070`, `dist_step_p2p5`, `dist_above_5`, `imu_stale_1p0`, `gnss_jump_5m`, `operator_link_lost`, `w2_040927_c06`, `start_threshold_p15`). 그중 6조건을 같은 seed로 한 번 더 돌려 trace·직렬·실행기 기록의 SHA-256이 같았다.
- `nominal` 조건을 `follow_matrix`의 run 이름(`follow_nominal_s0`)으로 만들면 주입기를 넣기 전 코드(main `89af3be`)의 `follow_matrix` nominal seed 0과 세 SHA-256이 같았다(조건을 끄면 기존 결과와 같음).
- 이 확인에서 본 것 두 가지를 적는다. ① `dist_step_p2p5`(+2.5 N·m)는 seed 9000에서 외란 2.4 s 뒤 MCU `STALL`로 섰다. 기준(크기 안 외란은 결함 0)은 바꾸지 않았다. ② 운영자 연결 끊김의 '구동 0' 시각을 처음에는 trace 행(10 ms 격자)으로 쟀고 0.56 s였다. 개정 31의 문구('구동 0 요청 송신')대로 실행기가 구동 0을 보낸 틱으로 재는 것으로 바꿨다(같은 run에서 0.55 s). 한도(0.5 s + 1틱)는 바꾸지 않았다. trace 행 값도 보고 칸 `link_trace_zero_s`로 남긴다.

| 열 모양 | `RowGeometry`: 열 폭, 나무 간격, 일정 곡률(굽은 열은 두 열 선이 호), 빠진 나무, 끝 기둥(반지름 0.06 m, G-SIM의 0.10 m 각 기둥), 그 밖의 기둥 → W0 기둥 목록 | 리그 신원 `world.markers`, RESULT의 spec |
| W2 | 10/10 개발 회랑(래스터 세계). 봉인 회랑은 리그가 거부한다 | 리그 신원 `world` |
| 출발 | 열 좌표 (s, d, 방향) → 세계 자세 | trace 참값 첫 행 |
| 차 | 프로필 덮어쓰기: 곡률 떠돎 평균(한쪽 쏠림, 프로필 범위 끝 ±0.6 °/m), 조향 영점, v0.3의 조향축 외란(`steer_torque` 주입, 지면 충격·미는 토크 과정) | 프로필 라벨·덮어쓰기(RESULT spec), MCU F 줄, trace 참값(`truth_delta_eq_rad` 등) |
| 구동 표 | 플랜트의 정상 속도 = 현장 조정 파일의 속도 표 × factor, duty에 duty_scale을 곱하고 duty_offset_pct를 뺀 값에서(`steered_plant.drive_table_spec`, `RigConfig.drive_table`). 실행기는 같은 파일을 자기 읽기 모듈로 읽는다 | 리그 신원 `drive_table`(파일 SHA-256), 실행기 기록 `tuning.file_sha256`, trace `truth_v_m_s` |
| 센서 | 리그 고장 `sensor_blackout`(lidar 또는 imu, 20 s부터) | 실행기 틱의 `lidar_age`, `imu_age` |

- 경사: 빠른 SIM은 경사를 모형으로 갖고 있지 않다(플랜트가 평면, IMU에 기울기 입력이 없음). 그래서 **모형 없음**으로 적고 이 등록에서 뺐다.
- 구동 표 주입은 기본 꺼짐이다(`drive_table` None이면 플랜트는 예전 구동 곡선 그대로). 켜면 run마다의 속도 배율 추첨(`speed_run_scale`)을 쓰지 않는다(표 × factor가 그 run의 차다). 속도 흔들림(1 + 흔들림)과 조향 끌림 손실은 그대로 둔다.
- '출발 문턱 +15 %p'는 표 전체를 duty 쪽으로 15 %p 옮긴 것이다(속도 = 표(duty − 15) × factor).

## 4. 재는 값

참값은 평가에만 쓴다(리그 trace의 `truth_*` 칸과 세계 기하, 참값 격리 역할 evaluator).

- 열 좌표: 곧은 열은 (s, d) = (x, y), 방향 오차 = 차 방향각. 굽은 열은 중심선 호에 대한 호 길이 s, 왼쪽 + 부호 거리 d, 차 방향각 − 그 점의 호 접선. W2는 회랑 좌표 칸 `truth_field_*`(카탈로그 중심선).
- 주행 구간: 구동 명령이 처음 0보다 큰 trace 행부터 마지막으로 0보다 큰 행까지.
- 횡오차 = 차체 중심(footprint 중심)의 d. 방향 오차 위와 같다. RMSE·p95·방향 RMSE는 주행 구간에서, 출발 어긋남 4조건은 주행 6.0 m 뒤부터 잰다(앞 등록과 같은 규칙). 최댓값은 주행 구간 처음부터.
- **열 끝 정지 위치 e = 정지 때 앞범퍼의 s − 열 줄에 있는 마지막 구조물의 s**(결정 R50). 앞범퍼 = 중심 + 0.61 m·(방향). 마지막 구조물 = 끝 기둥이 있으면 끝 기둥, 없으면 마지막 나무(빠진 나무는 셈하지 않음). W2는 카탈로그 두 열 선의 마지막 단위 s 중 큰 값. 옛 정의(마지막 나무 기준)의 값도 `row_end_error_last_tree_m`으로 남긴다(판정 아님).
- 최소 여유: 차체 사각형(1.22 × 0.70 m)에서 기둥 표면까지의 최소 거리(W0, trace 5행마다). W2는 래스터의 단단한 장애물 여유(`raster_corridor.footprint_clearances`의 hard, 25행마다).
- 일시정지: 주행 시작 뒤의 PAUSED 상태 전이와 이유.
- 종결 뒤 조향: A22 규칙(`measure.command_after`, 종결 시각부터 3 s, 일시정지로 끝난 run은 첫 일시정지 시각부터).
- 신선도 정지: 주행 시작 뒤 실행기 틱의 `lidar_age`가 0.45 s(또는 `imu_age`가 0.40 s)를 처음 넘은 틱부터 구동 명령(틱의 `T`)이 0인 첫 틱까지, 그 뒤 구동 명령이 다시 0보다 커지는지.
- 운영자 연결 끊김: 마지막 heartbeat(화면을 가린 틱 바로 앞 틱)부터 실행기가 구동 0을 보낸 첫 틱(틱의 `T` = 0)까지, 그 뒤 다시 커지는지.
- 조향 결함: MCU F 줄 중 조향 결함(POT_OPEN, POT_SHORT, POT_JUMP, POT_NOISE, POLARITY, DRV_STUCK, STALL, TRACK, THERMAL)의 코드와 시각(큐에 들어간 틱). 호스트 브리지 래치(실행기에는 조향 상태로만 보이는 평가 기록).
- GNSS: 실행기 마지막 틱의 `gnss` 블록(`fence_tripped`, 결과별 수 `jump`)과 가상 수신기 보고(튄 fix 수 `jumped`).

9. 동시에 도는 프로세스는 4개 이하다. 판정 값은 SIM 시간 값이고 seed마다 결정적이다(0절의 같은 seed 두 번 확인). 그래서 공통 규칙 11의 무거운 측정 잠금 없이 돈다. 시간 값(벽시계)은 참고로만 적는다.
