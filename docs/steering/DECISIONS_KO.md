## R11. 자리값 프로필에서 설계 표와 달라진 것(1단계 검토 반영)

- `servo_min_pwm_pct` 25 → 40 %. 조향 모터 시작 PWM(주행 중 25 %, 정지 중 35 %)보다 커야 서보가 데드밴드 안에 선다. 25 %에서는 목표보다 1.25~2.33° 앞에서 섰다. 같거나 작으면 `warnings()`와 결과 표지에 `servo_min_pwm_cannot_start_the_motor`가 남는다.
- DERIVED 범위가 입력 범위 전체가 주는 값을 덮게 넓혔다: `scrub_radius_m` −0.09~0.13, `pot_lsb_deg` 0.04~0.5. `servo_hz`는 선택지 {500, 1000}이다.
- DERIVED 값은 프로필 파일에 적지 않는다(적으면 `derived_value_written`으로 거부). 읽을 때 계산하고, 파일의 note에는 "자리값에서 약 …"으로만 적는다.
- 브래킷 여유는 바퀴가 차체 반폭 밖으로 나온 만큼(min(여유, 스윕))만 바퀴 바깥쪽으로 더한다. 각도에 대해 연속이다(직진 0.35 m, 기계 한계에서 0.0429 + 0.02 m).
- 정지 중 속도 ≤ 주행 중 속도, 정지 중 최소 PWM ≥ 주행 중 최소 PWM을 검사한다(프로필 `standstill_order`, C++ 시작 줄 종료 2). 그래서 `steer_rate_max_deg_s`와 `steer_min_pwm_pct`는 각각 정지 중 짝과 함께 스윕한다(P8 조건 정의에 반영).
- 기본 백엔드는 프로필의 `steer_actuator_level`을 따른다. 기본 프로필(L1)은 C++ 컴파일러가 필요하다. `geometry_check`는 L0이다(설계 3.3).
- 구동기 상태 응답(`steer_status()`)에는 명령한 값(`command_steer_pwm`, `steer_en`)만 있다. 드라이버의 실제 출력은 `truth()`에만 있고 그 칸 목록은 `backend_api.TRUTH_OUTPUT_FIELDS`다. A13 정적 검사는 이 목록을 쓴다.

## R14. 프로필 v0.1: `drive_tau_stall_nm` 1.6 → 4.4 N·m

- 이유: 사용자가 현장에서 PWM-이동거리 값과 가중치를 손으로 바꿔 가며 실험하겠다고 했다(계획 1절 20·21번). 계획 나16에서 이 묶음과 '정지 상태에서만 적용'을 정했다. 잘못된 값으로 달리는 일을 막는다.
- 바뀌는 기존 규칙: 새 절이다. `tools/row_executor/config.py`의 현장 조정 키 3개(`base_duty_pct`, `reduce_duty_pct`, `max_differential_pct`)는 조향판에서 쓰지 않는다. `DESIGN_v1_KO.md` 3.8 F표 `v_target_m_s`(604행)는 이 파일의 '목표 속도'로 옮긴다.
- 사용자 확인: 2026-11-12(계획 4절 나16 확정). 각 값의 시작값은 자리값이다.
- 맡는 작업: PW-07, PW-08, PC-13, PW-10, 화면 UI-12.

## R36. 조향 하드웨어 기본 가정: 벨트로 이은 가변저항, 일반 DC 모터, ESP 위치 루프, 리밋 스위치 없음

- 2026-11-12. 설계 v2 개정 V2-6.
- 사용자 설명(2026-11-11): 조향 장치와 가변저항을 벨트로 잇고, 가변저항 값을 기준으로 모터를 돌려 조향한다. 조향 모터는 서보가 아닌 일반 모터이고 모터 드라이버로 구동 바퀴처럼 돌린다.
- 선택:
  - 가변저항은 조향각 센서다(Q1 답). 조향 모터는 일반 DC 모터와 드라이버다(Q11 일부 답). 위치 루프는 ESP에서 닫고 Jetson은 목표각만 보낸다(Q4 답, 계획 가4).
  - 리밋 스위치는 없다고 본다. 끝 보호는 가변저항 소프트 한계, 기계 끝 멈춤, STALL·TRACK이다. 벨트가 미끄러지면 소프트 한계도 같이 어긋나므로 호스트에 '0점 이동' 감시(trim 적분이 한도의 80 % 넘음 또는 `steering_ineffective`)를 둔다.
  - 벨트 모형을 프로필 v0.2에 넣는다(ST-10): 벨트 비 범위를 1 미만도 받게(자리값 0.5~5), 범위 검사(조향 전 범위 × 비가 raw 60~963 안, 보정 반쪽 폭 ≥ 50 count), 측정 쪽 유격, 정상 운행 중 미끄럼(이 건너뜀, 누적 미끄럼), 끊어짐·벗겨짐, 조향 쪽 배터리 배율.
  - 자기 잠금은 기본 false(v1 그대로). 같은 ESP8266의 A안 핀 배치(v1 4.1절)를 기본으로 둔다.
  - 직진 유지 규칙: 프로필의 외란 크기 안에서는 래치 결함 없이 되돌아오고, 그보다 크면 정해진 결함으로 선다. 지금 TRACK·STALL·THERMAL 자리값과 맞지 않는 부분은 ST-10에서 정리한다.
- 이유: 계획 1절 2~5번, 가4. 지금 모형의 큰 틀과 같지만 벨트와 리밋 스위치에 대한 가정이 없었다(조사 `RESULT_steer_status.txt` '조향 하드웨어' 항목).
- 바뀌는 기존 규칙: `DESIGN_v1_KO.md` 3.3절(318행), 3.4절(354행), 3.8 C·E표(570행 `pot_to_steer_ratio` 범위 1~5), 9절 Q1·Q2·Q10·Q11의 기본값. 사양 요청서의 질문 개정은 ST-09에서 한다.
- 사용자 확인: 하드웨어 설명은 2026-11-11 사용자 메시지. 값(벨트 비, 유격, 조향 속도, 리밋 스위치 유무)은 미답이라 모두 자리값이다(계획 4절 다1).
- 맡는 작업: ST-09, ST-10, ST-11, ST-17.

## R37. 목표 속도 0.40 m/s(0.20~0.50), 열 끝 정지 위치는 v1 정의 그대로
