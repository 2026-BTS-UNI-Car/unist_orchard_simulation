# 사전등록: GNSS RTK 약한 제약 빠른 SIM 행렬 (`gnss_rtk_weak_v1`)

- 등록: 2026-11-16, 판정 run 전에 커밋한다. 결정 R100, 합격 기준 개정 100, 설계 [`GNSS_RTK_KO.md`](GNSS_RTK_KO.md).
- 기계가 읽는 등록: `PREREG_GNSS_RTK.json`(= `steering.safety_scripts.rtk_matrix.prereg()`; `sim/ubts/test_steering_rtk_matrix.py`가 비교한다). 조건, seed, 기준, 실행기 설정을 판정 run 뒤에 바꾸지 않는다. 바꿀 일이 생기면 이 문서에 개정을 먼저 적는다.
- 모든 수치는 **자리값 기반 SIM 결과**다. 가상 RTK 수신기는 자리값 모형이고, 실제 수신기가 나무 아래에서 어떻게 움직이는지는 잰 적이 없다. 현장 성능이 아니다.

## 1. 무엇을 보나

1. RTK가 나쁠 때(FLOAT만, 해 전이·끊김, 잘못된 FIXED의 계단·튐, 틀린 좌표계, 굽은 열) 해가 없는가.
2. RTK가 좋고 LiDAR 통로 중심이 치우친 곳(한쪽 열의 나무가 바깥으로 몰린 구간)에서 조금이라도 낫는가.
3. 전이에서 보정에 계단이 없는가(보정 상한, 변화 속도 한도).

## 2. 시뮬레이터와 설정

- 빠른 SIM T1 장치, 실행기 포함(`tools/row_executor/sim_in_loop_steer.py`). 측정 규칙은 `follow_wide.py`(2차 규칙: RowGeometry 열 좌표의 횡·방향 오차, 발자국, 마지막 구조물 기준 열 끝 e, A22).
- 프로필 둘:
  - `v01`: `front_steer_v0_1_placeholder`(기준 v0.1, 펌웨어 V3 서보), 제어기 `row_follow` 기본값(`steer_follow_v1`과 같음).
  - `v1`: `front_steer_v1_spec_20261116`(실측 치수, ABS-HOLD-8 흉내), 실행기 조향 GO 문턱 4.0 °/s와 제어기 휠베이스 0.657 m(`steer_follow_realdims_v1`과 같음).
- 세계(W0 기둥 두 줄, 폭 3.5 m, 1.5 m 간격, 열 끝 40 m):
  - `nominal`: 곧은 열.
  - `jog_r`: 오른쪽 열의 나무 4그루(s 21.0, 22.5, 24.0, 25.5 m)가 0.35 m 바깥에 있다. 심은 선(판정 기준 중심선)은 곧다. LiDAR 통로 중심이 그쪽으로 끌린다(개발 run에서 0.07~0.15 m).
  - `curve_l60`: 반지름 60 m로 왼쪽으로 휜 열.
- 모든 rtk run에는 쌍(`off`)이 있다: 같은 프로필, 세계, seed, 난수 흐름 이름(그래서 플랜트·LiDAR·IMU 잡음이 같다. 가상 GNSS는 자기 흐름), 실행기 `gnss_mode` `off`, GNSS 패킷 없음.
- rtk run의 실행기: `gnss_mode` `weak_constraint`, 그 밖의 `gnss_rtk_*`는 기본값(FIXED만, hAcc ≤ 0.05 m, 이득 0.5, 상한 0.10 m, 0.05 m/s, 1.5 s, 창 20 m, 최소 길이 8 m, 레버암 0). `RtkSettings`의 나머지 값(학습 늦춤 2 m, 학습 문 0.03 m, 다시 맞춤 5 m, 방향 문 3°, 거른 불일치 0.20 m, 좌표계 확인 0.01 m·0.05 m·2배 등)은 JSON의 `executor.rtk_settings`에 그대로 적었다.
- 가상 수신기: 5 Hz(위상 30 ms), 지연 0.1 s, RTK 모형 자리값(FIXED hAcc 0.014 m·흰 0.008 m·떠돎 0.006 m/30 s, FLOAT hAcc 0.25 m·흰 0.06 m·떠돎 0.20 m/20 s).
- seed: 개발 100·101(조건과 규칙을 고르는 데 썼다), 판정 6000~6004(이 등록 뒤 처음 돌린다).

## 3. 조건

시간은 SIM 초다(개발 run: 출발 약 3.5 s 뒤 0.4 m/s 가까이, s 21~28.5 m를 t 약 56~77 s에 지난다).

| 이름 | 세계 | 수신기 | 역할 | 보는 것 |
|---|---|---|---|---|
| `nominal_fixed` | nominal | FIXED 내내 | 해 없음 | LiDAR가 좋을 때 RTK가 흔들지 않는가 |
| `jog_fixed` | jog_r | FIXED 내내 | 이득 | 치우친 LiDAR를 조금 당기는가 |
| `jog_float_only` | jog_r | FLOAT 내내 | 같음 | 기본 설정(FIXED만)에서 한 번도 걸리지 않는가 |
| `jog_fixed_transitions` | jog_r | FIXED, 60~66 s FLOAT, 66~70 s 없음, 76~79 s 단독 | 해 없음 | 전이에서 계단 없이 줄어드는가 |
| `jog_fixed_jump` | jog_r | FIXED, 59~65 s 0.49 m 계단(잘못된 FIXED), 70 s·75 s 한 fix 튐 0.36 m·0.39 m | 해 없음 | 튐·계단을 걸러 내는가 |
| `nominal_mirror` | nominal | FIXED, 동·북이 바뀐 좌표계 | 같음 | 틀린 좌표계를 거부하는가 |
| `jog_lever` | jog_r | FIXED, 안테나가 차체 기준점보다 0.5 m 앞·0.2 m 왼쪽(실행기는 0으로 앎) | 이득 | 레버암 오차에도 쓸 만한가 |
| `curve_fixed` | curve_l60 | FIXED 내내 | 해 없음 | 직선 모형이 굽은 열을 해치지 않는가 |

run 수: 프로필 2 × seed 5 × (조건 8 + off 쌍 3) = 110.

## 4. 기준

run마다(모든 rtk run):

1. `follow_wide.judge`의 `row_end` 검사를 모두 통과(2차 기준: 횡 RMSE ≤ 0.20 m, p95 ≤ 0.35 m, 최대 ≤ 0.50 m, 방향 RMSE ≤ 5°, 최대 ≤ 15°, 참 속도 ≤ 0.50 m/s, e ±1.0 m, 접촉 없음, 정지, A22). off 쌍도 같은 검사를 받는다(off 실패는 그 자체로 적는다).
2. 끝난 이유가 off 쌍과 같다.
3. 모든 틱에서 |보정| ≤ 0.10 m(기록 반올림 여유 1e-4 m).
4. 틱 사이 보정 변화 ≤ 0.05 m/s × 틱 간격(여유 2e-4 m). 계단 없음.
5. 역할 '같음': 조향·구동 명령 열이 off 쌍과 같다(SHA-256), 보정이 내내 0이었다(최대 |보정| = 0).

(프로필, 조건)마다 seed 5개로(역할 '해 없음'과 '이득'):

6. 평균 횡 RMSE ≤ off 평균 + 0.02 m.
7. 평균 횡 최대 ≤ off 평균 + 0.05 m.

역할 '이득'에 더해:

8. jog 구간(s 21.0~28.5 m, 주행 중) 평균 |d|의 seed 평균이 off보다 10 % 이상 작다.
9. jog 구간 평균 |d|가 off보다 크지 않은 seed가 절반보다 많다.

run 기준을 run 하나가 아니라 (프로필, 조건)의 평균으로 둔 6·7의 까닭: 개발 run에서 `v1`(펄스 조향) 정상 run 하나가 보정 최대 0.013 m에서 횡 최대 +0.053 m였다. 작은 입력 차이가 펄스 시점을 바꿔 궤적이 갈린다. run마다의 차이는 보고한다(판정 안 함).

판정: 1~9를 모두 만족하면 합격. 실패는 실패로 적고, 판정 seed로 고쳐 다시 재지 않는다(이 등록에는 반복이 없다).
